# Внешние модели

Сюда кладутся необязательные модели. **Игра работает и без них**: пока
файла нет, используются процедурные. Если файл положили, а он битый или
не грузится — в консоли предупреждение, в игре остаётся процедурная
версия. Сломать игру неудачной моделью нельзя.

## Форматы

| Формат | Работает | Что важно знать |
|---|---|---|
| **.glb** | ✅ лучший вариант | Один файл: меш, материалы, текстуры, скелет, анимации |
| **.gltf** | ✅ | Тащит за собой отдельные файлы текстур — клади их рядом |
| **.fbx** | ✅ | Со скелетом и анимациями. Часто в сантиметрах → `scale: 0.01` |
| **.obj** | ⚠️ | Только геометрия. **Нет скелета** → пальцы не согнуть. Материалы в отдельном `.mtl` |
| **.blend** | ❌ | Внутренний формат Blender, браузер его не читает. Нужен экспорт |

## Как перегнать .blend или .fbx в .glb

Занимает минуту, и результат лучше по всем статьям — один файл, меньше
весит, быстрее грузится.

1. Открой файл в Blender (бесплатный, blender.org)
2. **File → Export → glTF 2.0 (.glb/.gltf)**
3. Формат: **glTF Binary (.glb)**
4. В панели справа: включи **Include → Selected Objects** (если нужна
   только часть), в разделе **Data → Mesh** оставь всё по умолчанию,
   в **Data → Armature** включи **Export Deformation Bones Only**
5. Сохрани как `assets/hands.glb`

Draco-сжатие **не включай** — декодер не подключён.

## Как подключить

1. Положи файл в эту папку
2. В `js/config.js` пропиши путь в блоке `ASSETS`:

```js
export const ASSETS = {
  hands: {
    url: 'assets/hands.glb',
    fit: { scale: 1, rotX: 0, rotY: 0, rotZ: 0, x: 0, y: 0, z: 0 },
    bendAxis: 'z',
    bendSign: 1,
    ...
  },
};
```

3. Открой игру, нажми **F12** и посмотри, что внутри модели:

```js
__inspectAsset('hands')
```

Он напечатает список мешей, число костей, габарит модели в метрах и
подскажет масштаб. По этим данным и подгоняется `fit`.

## Подгонка

- **Модель огромная или микроскопическая** → `fit.scale`. Инспектор
  подсказывает значение исходя из роста 1,75 м
- **Лежит на боку или смотрит не туда** → `fit.rotX/rotY/rotZ` (радианы,
  `Math.PI/2` это 90°)
- **Смещена** → `fit.x/y/z`
- **Кулак выворачивается наизнанку** → `bendAxis` ('x', 'y' или 'z') и
  `bendSign` (1 или -1)

## Если модель — целый человек

Полноценная модель человека годится под руки от первого лица, только
если из неё можно выкинуть лишнее. Для этого есть фильтры:

```js
fit: {
  only: ['hand', 'forearm'],   // оставить только совпавшие меши
  // или
  hide: ['head', 'torso', 'leg'],  // спрятать совпавшие
}
```

Имена мешей смотри через `__inspectAsset`. **Если модель — один сплошной
меш, разделить нечего**: спрятать можно только целиком. Такая модель
пригодится не под руки, а под вид на себя сверху вниз — ноги и торс,
когда смотришь под ноги.

| `feet` | `feet.glb` | 106 КБ | Одна ступня, вторая зеркалом. Прорежена из скульпта на 436 тыс. вершин |
| `uaz` | `uaz.glb` + `uaz.png` | 728 + 328 КБ | УАЗ-469 на приёмном пункте. Вынут из `.blend`, текстура рядом файлом |
| `buyer` | `Join.fbx` | 915 КБ | Скупщик, стоит у водительской двери УАЗа |

Про кости: у скачанных ригов они часто называются `Bone001`, `Bone002`
и так далее. Разобрать такие имена нельзя, поэтому игра умеет ставить
пальцы **по структуре скелета**: корневая кость запястья, от неё пять
цепочек, самая короткая — большой палец. Ничего прописывать не нужно.

Какая рука в модели — определяется по большому пальцу: он всегда смещён
в сторону ладони. На глаз это не различить, кулак с обеих сторон
выглядит одинаково, поэтому в конфиге стоит явное `side`.

## .blend без Blender

Формат `.blend` не читает ни один браузерный загрузчик, а ставить ради
одной модели Blender необязательно: файл разбирается программно.

```bash
pip install blender-asset-tracer
python tools/blend2glb.py path/to/UAZ.blend assets/uaz.glb uaz.png 4.1
```

Последний аргумент — длина модели в метрах по самой длинной оси; скрипт сам
масштабирует, разворачивает Z-вверх в Y-вверх, ставит модель колёсами
на ноль и центрует по горизонтали. Текстуру (третий аргумент) надо
положить рядом с `.glb` самому — скрипт только прописывает ссылку.

Подводный камень: в Blender 2.7x развёртка лежит в `MLoopUV`, где
кроме самих `uv` есть ещё поле `flag`, и шаг структуры не 8 байт, а 12.
Прочитаешь с шагом 8 — модель выйдет белой, текстура ляжет в пустой
угол атласа. Скрипт берёт размер из DNA файла, а не на глаз.

## Тяжёлые модели: прореживание

Скульпты из ZBrush приходят с сотнями тысяч вершин. Ступня в исходнике
весила **5,9 МБ и 436 308 вершин** — для детали, которую видно с полутора
метров, это на два порядка больше нужного.

В папке `tools/` лежат две страницы, которые открываются с локального
сервера:

- **`tools/model-prep.html`** — грузит FBX, прореживает кластеризацией
  по сетке, ставит модель в игровые метры и ориентацию, экспортирует
  `.glb` и кладёт его в `assets/`. Прогон ступни: 436 308 → 2 895 вершин,
  5,9 МБ → 106 КБ, и на глаз разницы нет.
- **`tools/model-view.html?url=../assets/feet.glb`** — смотрит любую
  модель с четырёх сторон и печатает габарит и число треугольников.

Сохранение из `model-prep.html` работает только на локальном сервере с
поддержкой PUT — на GitHub Pages страница просто ничего не сохранит.

## Битый FBX: осиротевшие текстуры

Если FBX валится с `Cannot read properties of undefined (reading
'children')` — в нём остались узлы `Texture` без связей: текстуры к
модели не приложили, а ссылки на них остались. Загрузчик three на таком
падает.

Лечится переименованием узлов прямо в двоичном файле — длина имени та
же, смещения не съезжают:

```python
b = open('assets/knife.fbx', 'rb').read()
open('assets/knife.fbx', 'wb').write(b.replace(b'Texture', b'_unused'))
```

Так и починен `knife.fbx`.
